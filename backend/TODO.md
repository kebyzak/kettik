# backend · задачи

## Вход по коду на почту

Игрок вводит почту, получает 6-значный код, вводит его и входит. Пароля нет.
Если такой почты ещё нет, после кода спрашиваем имя: оно нужно для состава игры.

### API

- `POST /auth/code {email}` → `204`. Ответ одинаковый, есть такая почта или нет.
- `POST /auth/verify {email, code}` → `{token, player | null}`. `player: null` значит новый игрок, дальше `POST /me {name}`.

### Правила

- Почту приводим к виду `trim + lowercase` один раз на входе и дальше доверяем.
- Код живёт 10 минут. В базе храним только хеш кода, сам код не храним.
- На один код даём 5 попыток, после этого код сгорает.
- Новый код можно запросить не раньше чем через 60 с. Новый код отменяет старый.
- Лимит запросов: на почту и на IP в час, чтобы нас не использовали для рассылки.
- Повторный `verify` с уже использованным кодом не создаёт вторую сессию и второго игрока.
- Токен сессии долгоживущий, его можно отозвать (выход, потеря телефона).

### Отправка

- Используем транзакционный почтовый сервис с бесплатным тарифом: Resend, Brevo или Amazon SES (у SES не бесплатно, но очень дёшево). Лимиты тарифов проверить перед выбором.
- Провайдер прячем за одной функцией `sendCode(email, code)`, чтобы его можно было сменить.
- Отправляем со своего домена и настраиваем SPF, DKIM и DMARC, иначе письма уйдут в спам.
- Письмо короткое: код в теме и в первой строке, чтобы его было видно из уведомления.
